# Chess Benchmarks (SAN v1)

This project evaluates prompt systems on chess tasks using **full FEN (6 fields)** as the canonical board state. The initial focus is **legal move generation** with **SAN** (future: UCI support).

## Common input fields (recommended)

- `position_fen` (string, required): Full FEN, e.g. `"rnbqkbnr/pppppppp/8/8/8/8/PPPPPPPP/RNBQKBNR w KQkq - 0 1"`.
- `board_context` (string, optional): A deterministic, human-readable block derived from the FEN (see `CHESS_STATE_V1`). Generated by `scripts/chess/generate_scenarios.py`.
- `move_notation` (string, optional): `"san"` today. (The evaluator already supports `"uci"` for future expansion.)
- `illegal_moves` (array[string], optional): Prior moves to avoid (used for retry loops in move generation).

Baseline chess systems in this repo generally only *use* `position_fen` (and `illegal_moves` for retries); the extra fields are for convenience and future expansion.

## Script: random benchmark suite (`scripts/chess/benchmark_random.py`)

Preferred entrypoint when you want to generate **random positions on the fly** and treat **`--iterations` as “number of games/positions”** (each position is evaluated once).

It can run:

- **Validator baseline**: legality-check system on random labeled moves (oracle label via `python-chess`).
- **Generator baseline**: move-generation system → oracle legality rate.
- **Validator-on-generator**: legality-check system judging the generator’s move (compare to oracle).
- **Generator→validator pipeline**: retry generator with `illegal_moves` until validator accepts (or attempts exhausted).

### Arguments

- `--iterations N` (default: `100`): Number of random positions generated (each run once).
- `--plies N` (default: `8`): Random legal plies to play before sampling a position.
- `--seed N` (default: `1`): Deterministic RNG seed for position generation.
- `--illegal-ratio R` (default: `0.5`): Fraction of validator-baseline cases labeled illegal.
- `--generator-system PATH`: Move generator system YAML/JSON (optional).
- `--generator-output-field FIELD` (default: `move_san`): Move field in generator `system_output`.
- `--validator-system PATH`: Legality-check system YAML/JSON (optional).
- `--validator-output-field FIELD` (default: `is_legal`): Boolean legality field in validator `system_output`.
- `--pipeline-max-attempts N` (default: `3`): Max generator attempts per position in pipeline mode.
- `--run-dir DIR` (default: `runs/benchmarks`): Root directory for artifacts.
- `--log-level LEVEL` (default: `INFO`): `DEBUG | INFO | WARNING | ERROR`.
- `--log-file PATH|auto` (default: `auto`): Log file; `auto` writes `benchmark.log` into the benchmark directory.
- `--progress-every N` (default: `10`): Progress logging interval (set `0` to disable).

### Artifacts

Each benchmark run writes a directory like `runs/benchmarks/<benchmark_id>/` containing:

- `manifest.json`, `positions.jsonl`, `results.jsonl`, `summary.json`
- `psf_runs/<system_id>/<run_id>/...` with per-run **prompts + outputs** (`nodes.jsonl`) and token metrics (`run.json`)

### Examples

Validator-only (random labeled moves):

```bash
.venv/bin/python scripts/chess/benchmark_random.py \
  --iterations 200 \
  --plies 8 \
  --seed 1 \
  --validator-system systems/chess_san_legal_check_yn_system.yaml
```

Generator-only:

```bash
.venv/bin/python scripts/chess/benchmark_random.py \
  --iterations 200 \
  --plies 8 \
  --seed 1 \
  --generator-system systems/chess_san_move_generator_system.yaml
```

Generator vs generator→validator pipeline (shared random positions):

```bash
.venv/bin/python scripts/chess/benchmark_random.py \
  --iterations 200 \
  --plies 8 \
  --seed 1 \
  --generator-system systems/chess_san_move_generator_system.yaml \
  --validator-system systems/chess_san_legal_check_yn_system.yaml \
  --pipeline-max-attempts 3 \
  --log-level INFO \
  --log-file auto
```

## Script: scenario generation (`scripts/chess/generate_scenarios.py`)

Generates deterministic random positions by playing N random legal plies from the starting position, then writes scenario JSON files into an output directory.

### Tasks

- `legal_check_san`: emits labeled scenarios with `candidate_move` and `expected_legality`.
- `move_generation_san`: emits unlabeled scenarios for move generation, optionally used with `illegal_moves` during retries.

### Arguments

- `--task {legal_check_san,move_generation_san}`: Which scenario family to generate.
- `--out-dir PATH`: Directory where JSON scenarios are written.
- `--count N` (default: `100`): Number of scenarios to generate.
- `--plies N` (default: `8`): Random legal plies to play before sampling the final position.
- `--seed N` (default: `1`): Deterministic RNG seed (same seed → same scenarios).
- `--illegal-ratio R` (default: `0.5`, `legal_check_san` only): Fraction of scenarios labeled illegal.
- `--overwrite`: Allow writing into a non-empty `--out-dir`.
- `--progress-every N` (default: `25`): Log progress every N scenarios (set `0` to disable).
- `--log-level LEVEL` (default: `WARNING`): `DEBUG | INFO | WARNING | ERROR`.
- `--log-file PATH|auto` (default: unset): Write logs to a file. Use `auto` to write `generate.log` into `--out-dir`.

### Examples

Generate 200 labeled legality-check scenarios:

```bash
.venv/bin/python scripts/chess/generate_scenarios.py \
  --task legal_check_san \
  --out-dir examples/input/chess/legal_check_san \
  --count 200 \
  --plies 8 \
  --seed 1 \
  --overwrite
```

Generate 200 move-generation scenarios with progress logs:

```bash
.venv/bin/python scripts/chess/generate_scenarios.py \
  --task move_generation_san \
  --out-dir examples/input/chess/move_generation_san \
  --count 200 \
  --plies 8 \
  --seed 1 \
  --overwrite \
  --log-level INFO
```

## Benchmark: legal check (SAN → Y/N) via PSF CLI

Use the built-in benchmark runner when you have `expected_legality` in each scenario.

### Systems

- `systems/chess_san_legal_check_yn_system.yaml`: minimal baseline that answers Y/N and parses to `is_legal`.
- `systems/move_validator_system.yaml`: richer validator baseline (structured output).

### Arguments (PSF)

Key flags for `psf benchmark`:

- `--system PATH` (repeatable): One or more systems to benchmark.
- `--inputs-dir DIR`: Directory of labeled scenario inputs.
- `--iterations N`: Repeats per scenario.
- `--expect-field FIELD`: Field containing ground truth (default: `expected_legality`).
- `--output-field FIELD`: Field in system output to compare (e.g. `is_legal`).
- `--run-dir DIR`: Where artifacts are stored (default: `runs`).

### Example

```bash
.venv/bin/psf benchmark \
  --system systems/chess_san_legal_check_yn_system.yaml \
  --inputs-dir examples/input/chess/legal_check_san \
  --iterations 20 \
  --expect-field expected_legality \
  --output-field is_legal
```

## Script: evaluate move generation (`scripts/chess/evaluate_move_generation.py`)

Evaluates a move-generation system by extracting a move field from `system_output` and checking legality with `python-chess` (the “oracle”).

### Run modes

1) **Oracle-only** (default): run generator once per scenario/iteration; oracle scores parse+legality.
2) **Generator→validator loop** (optional): after each generated move, run a validator system; if rejected, retry generation with `illegal_moves` appended.

### Arguments

- `--system PATH` (required): Move-generation system YAML/JSON.
- `--inputs-dir DIR` (required): Directory of scenario JSON files (unlabeled).
- `--iterations N` (default: `10`): Runs per scenario.
- `--output-field FIELD` (default: `move_san`): Field in `system_output` containing the move string.
- `--validator-system PATH` (optional): If set, runs generator→validator loop.
- `--validator-output-field FIELD` (default: `is_legal`): Boolean output field in validator system output.
- `--max-attempts N` (default: `3`): Generator attempts per run when validator loop is enabled.
- `--run-dir DIR` (default: `runs/benchmarks`): Root for benchmark artifacts (subfolders are created).
- `--progress-every N` (default: `25`): Log progress every N runs (set `0` to disable).
- `--log-level LEVEL` (default: `WARNING`): `DEBUG | INFO | WARNING | ERROR`.
- `--log-file PATH|auto` (default: unset): Write logs to a file. Use `auto` to write `run.log` into the benchmark artifacts directory.

### Artifacts

Each run writes:

- `results.jsonl`: one JSON record per scenario+iteration (includes attempts and oracle verdict)
- `summary.json`: aggregate rates (oracle parse rate, oracle legal rate, failures, etc.)
- `psf_runs/`: per-attempt PSF run logs (prompt + raw output per node in `nodes.jsonl`, plus token metrics in `run.json`)
- optional `run.log`: if `--log-file` is set

### Examples

Oracle-only evaluation:

```bash
.venv/bin/python scripts/chess/evaluate_move_generation.py \
  --system systems/chess_san_move_generator_system.yaml \
  --inputs-dir examples/input/chess/move_generation_san \
  --iterations 20
```

Generator→validator loop with detailed logs:

```bash
.venv/bin/python scripts/chess/evaluate_move_generation.py \
  --system systems/chess_san_move_generator_system.yaml \
  --inputs-dir examples/input/chess/move_generation_san \
  --iterations 20 \
  --validator-system systems/chess_san_legal_check_yn_system.yaml \
  --max-attempts 3 \
  --log-level DEBUG \
  --log-file auto
```
